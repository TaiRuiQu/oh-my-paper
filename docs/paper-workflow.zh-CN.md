# 试卷解析、标准答案与批改流程

本文描述当前实现。试卷解析版本为 `exam-pipeline-4-crop-agents`，批改版本为 `exam-grading-3-full-answer-agent`。模型配置见 [AI 提供商与提示词](ai-providers-and-prompts.md)，评分规则见 [AI 批改](ai-grading.md)。

## 试卷录入

用户在试卷板块上传 PDF、JPG/JPEG 或 PNG；多张图片可以组成同一份试卷。上传时可选择是否生成标准答案与解题解析，默认开启。

1. **全卷题目识别。** 文件先渲染或转换为正向页面。`inventory` 模型在一次请求中看到所有页面，识别题目总数、板块、题号、分值和每题所在页码，包括跨页续题。此阶段不输出题目框或转录正文。答案页、答题卡上的编号不构成新题；教案中真实存在的题干仍应识别。分值可以依据总分和题型推测，保留 `printed`、`inferred` 或 `unknown` 来源及推测依据，之后允许用户修改。
2. **逐题精细定位。** 每道题独立请求 `localization` 模型，输入该题涉及的完整页面和坐标辅助图。模型只标注整题的 bounding box，以及表格、图形、图片等非文字材料的 bounding box。跨页或跨栏题目保留多个有序区域。程序校验材料框位于整题范围内，并分配稳定的材料 ID。
3. **裁切图文本化。** 程序先按整题框裁切，再为每道题启动 `transcription` Agent。Agent 只接收本题的有序裁切图及材料目录，通过受限的 `inspect_crop` 工具放大这些裁切图。题干、选项、公式、小问转为文本；非文字材料通过 ID 插入对应内容块的位置。程序校验材料没有遗漏、重复或虚构引用，并记录每个小问、每个填空的 `answerTargets`。题目文本排除学生作答、教师讲解和参考答案。
4. **整理或生成标准答案。** 印刷参考答案与评分标准单独提取，优先用于整理本题的标准答案。启用生成时，`solution` 模型按题接收电子题目和必要的干净材料图，为每个作答项输出答案、客观题选项及解题解析，并保存评分标准。关闭生成且没有参考答案时跳过求解；已有参考答案仍会整理，原件未给出的解析可以留空。
5. **保存与编辑。** 输出包含 `exam.json`、`exam.md`、核对记录、整题裁切图和材料图。用户可对照原件修正题干、分值、标准答案和评分标准。保存编辑生成新版本，过期编辑会被拒绝。未生成或不完整的标准答案可以在保存后点击“补生成标准答案”；该任务使用当前保存的题目和图像，不重新识别原件。

坐标统一使用正向完整页面的归一化 `x / y / width / height`，跨页区域各自记录 `page`。文本化 Agent 的裁切坐标由程序映射回整页。受到学生笔迹或批注污染的材料保留原图证据和核对提示，缺少可用的干净材料时求解保留未完成状态。

## 作答解析与批改

批改板块支持两种入口：

- **选择已保存题套。** 上传已作答试卷或答题卡，复用题套中的题目、标准答案、评分标准和干净材料图。提交时固定题套版本；学生扫描件只用于提取作答。题套必须已有完整可用的标准答案。
- **直接上传完整作答卷。** 可以不选题套，先按上述流程建立题套、准备标准答案，再解析作答并批改。只有作答而没有题干的答题卡需要选择对应题套。

作答解析使用 `answer_extraction` 模型，先根据题套结构定位整卷作答证据，再将有序裁切图交给答案文本化 Agent。定位和转录都不接收标准答案。可转文本的内容转为文本，图形、表格和无法文本表达的作答保存为图像，并按原顺序插入 `blocks`。

完整结果保存在 `answerDocument`，包含每个片段的 `sourceId`、题号或板块提示、原图区域、内容块、明确空白与无法辨认状态。题号无法确定的片段仍会保留，不提前丢弃。

随后为每道题独立启动 `grading` Agent。每个 Agent 收到同一份完整 `answerDocument`、所有非文字作答图、本题的电子题目、固定标准答案和评分标准。Agent 自行判断哪些片段属于本题，返回 `matchedSourceIds`、有序作答内容及逐评分点评分。解析阶段的题号提示可以被纠正。

用户选择不生成答案时，必须先补充或生成所选题目的标准答案才能创建批改任务。批改阶段复用保存的答案。答案归属不明、不可辨认、必要证据缺失或分值未知时保留待核对；只有完整作答文档中明确匹配到的空白证据才能按未作答记零分。

教师批次先选择题套，再逐位添加学生及其多页作答。批次固定题套的 `outputKey`，后续修改题套不会更改已有批次。每位学生独立处理，失败项可重试。

## 模型、校验与产物

六个阶段分别选择提供商配置，所选配置包含模型、提示词预设、并发数、输出上限和超时。逐题定位、文本化、求解与批改按相应模型的并发设置调度；同一供应商在一个 Worker 进程内共享请求调度器。配置变更作用于新提交的任务。

程序检查题目总数、页面覆盖、分值合计、框包含关系、材料引用、作答项答案和评分点。发现裁切遗漏时允许一次重新定位并再次文本化；持续失败保留题目身份、原图证据及待核对原因。Agent 有调用和时间上限。

识别状态 `verified` 表示程序校验通过，模型仍可能转录或解答错误。真实样例的结构检查与准确率边界见 [真实样例验证](exam-parsing-validation.md)。
