# v0.1.10 部署与升级指南

本版本默认使用流式模型 API，保留原卷纸张与分栏布局，并改进练习册识别、批量答案生成和 Responses 网关兼容性。

## 功能变化

- 试卷识别、答案生成、答案解析与批改 Agent 使用 `ToolLoopAgent.stream()`；答题卡单题评分和直接 JSON 生成使用 `streamText()`。后台持续消费流，管理员活动记录每轮开始输出的时间。工具在模型响应完整结束后执行，最终 JSON 经校验后保存。
- 请求超时分别限制等待响应头、等待首次有效输出和后续输出间隔。文本、思考与工具参数增量属于有效输出，SSE 心跳不算。持续输出可以超过单次超时值；Agent 任务保留 25 分钟总上限。流中断、超时和不完整结果会使任务失败，已保存草稿可继续重试。
- OpenAI Chat 兼容接口请求流末尾的 token 用量，用于 credit 结算。Responses 流直接由 SDK 解析，错误的 Content-Type 不会使后台等待完整响应体。
- 试卷保存原卷 A3/A4、方向和 1–4 栏布局，编辑与导出沿用这些信息。识别支持上传练习册节选和未知题数，不再依赖完整卷面题数。
- 答案 Agent 可一次读取并保存 1–50 道题，支持无分值练习册；批改继续按题保存与计分。
- 第三方 Responses 网关显式推理强度按配置发送，保留 `system` 角色，不额外请求推理摘要。后续轮次只回传可恢复的加密推理状态，并保留文本和工具上下文。
- Worker Compose 配置补充 `systempaths=unconfined`，修复 Docker 屏蔽 `/proc` 导致 Python 沙箱启动失败的问题。

## 升级

从 v0.1.9 升级包含新增 `Exam.layout` 的数据库迁移。备份后执行迁移，Web 和 Worker 使用同一版本。本次没有新增必填环境变量。镜像支持 `linux/amd64`：

```text
ghcr.io/tairuiqu/oh-my-paper:v0.1.10
ghcr.io/tairuiqu/oh-my-paper-worker:v0.1.10
```

发布工作流同时更新两个镜像的 `latest` 标签。固定版本时在 `.env` 中设置 `APP_VERSION=v0.1.10`。自动更新镜像不会同步 Compose 文件，因此旧部署必须先更新仓库中的 `compose.yaml` 和 `deploy/update.sh`。

手动升级时暂停原有定时升级，在部署目录获取版本并备份：

```bash
cd /opt/oh-my-paper
git fetch origin --tags
git checkout --detach v0.1.10
sudo bash scripts/backup.sh /var/backups/oh-my-paper
sudo install -m 600 .env /var/backups/oh-my-paper/pre-v0.1.10.env
```

保留数据库、存储目录和密钥，将 `.env` 的 `APP_VERSION` 设为 `v0.1.10`；当前 shell 若另有该变量，先执行 `unset APP_VERSION`。然后运行：

```bash
docker compose -f compose.yaml -f compose.release.yaml pull migrate web worker
docker compose -f compose.yaml -f compose.release.yaml stop web worker
docker compose -f compose.yaml -f compose.release.yaml up -d db
docker compose -f compose.yaml -f compose.release.yaml run --rm migrate
docker compose -f compose.yaml -f compose.release.yaml up -d --wait web worker proxy
docker compose -f compose.yaml -f compose.release.yaml ps -a
docker compose -f compose.yaml -f compose.release.yaml logs --tail=100 migrate web worker
```

确认 Web、Worker 为 `healthy`，页面显示 `v0.1.10`，并验证试卷识别、标准答案与单题评分。使用沙箱时，`docker inspect` 中 Worker 的 `HostConfig.MaskedPaths` 和 `HostConfig.ReadonlyPaths` 应均为 `[]`。首次部署和定时升级配置参见[通用部署手册](../deployment.zh-CN.md)。

## 验证范围

发布前通过格式检查、Lint、类型检查、248 项单元测试、数据库集成测试、答题卡批改集成测试，以及 Web 和 Worker 生产构建。流式测试覆盖四种接口、最终 token 用量、工具调用、结算失败、连接中断、取消、首次输出超时、输出间隔超时、SSE 心跳和不完整 JSON 响应。

模型回归使用模拟 SSE 响应，不调用外部模型；第三方网关的实际流式支持仍取决于所配置的接口。
