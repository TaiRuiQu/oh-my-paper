# v0.1.6 部署与升级指南

模型调用耗时观测：Agent 的每个 HTTP 请求现按「等待响应头 / 接收响应体」分别计时并记录状态码与失败标记，与输入输出 token 数、每秒输出 token 一起作为 `timing` 事件按轮上报，识别活动面板逐轮展示。结构化输出模式被移除，改为从模型文本中容错提取 JSON（含围栏代码块）再交 zod 校验；供应商设置里的结构化输出开关同步删除。

沙箱健壮性与可诊断性修复：bwrap 进程意外退出（宿主机安全配置、OOM 等）后，不再让整个识别任务的 `python` / `shell` 工具永久失效——下一次调用会自动重建沙箱，`/workspace` 重置为初始页面，并在返回的 stdout 首行附 `[沙箱进程已重启…]` 提示。已知 bwrap 报错（用户命名空间被宿主机限制、容器拒绝 proc 挂载、缺少 bubblewrap）现在会在工具失败信息中直接给出对应修复指引。Worker 启动时用与真实调用一致的完整参数做沙箱自检，环境不可用时输出 `worker.sandbox.unavailable` 日志（含诊断与建议）。

## 升级

本版本无新增数据库迁移或必填环境变量，Web 和 Worker 使用相同版本。已发布镜像支持 `linux/amd64`：

```text
ghcr.io/tairuiqu/oh-my-paper:v0.1.6
ghcr.io/tairuiqu/oh-my-paper-worker:v0.1.6
```

暂停原有定时升级后，在部署目录获取本版本并备份：

```bash
cd /opt/oh-my-paper
git fetch origin --tags
git checkout --detach v0.1.6
sudo bash scripts/backup.sh /var/backups/oh-my-paper
sudo install -m 600 .env /var/backups/oh-my-paper/pre-v0.1.6.env
```

保留数据库、存储目录及密钥，在 `.env` 中设置 `APP_VERSION=v0.1.6`。当前 shell 若设置了 `APP_VERSION`，先执行 `unset APP_VERSION`。更新 Compose 配置后执行：

```bash
docker compose -f compose.yaml -f compose.release.yaml pull migrate web worker
docker compose -f compose.yaml -f compose.release.yaml stop web worker
docker compose -f compose.yaml -f compose.release.yaml up -d db
docker compose -f compose.yaml -f compose.release.yaml run --rm migrate
docker compose -f compose.yaml -f compose.release.yaml up -d --wait web worker proxy
docker compose -f compose.yaml -f compose.release.yaml ps -a
docker compose -f compose.yaml -f compose.release.yaml logs --tail=100 migrate web worker
```

迁移成功后启动应用；Web 和 Worker 应显示 `healthy`。升级后建议确认 Worker 日志没有 `worker.sandbox.unavailable`，并跑一次试卷识别验证 `python` / `shell` 工具可用（沙箱环境问题排查参见[部署手册 §8](../deployment.zh-CN.md#8-故障排查)）。

首次部署及源码构建参见[通用部署手册](../deployment.zh-CN.md)。需要回滚至 v0.1.5 时，同步切换代码 tag 与 `.env` 的 `APP_VERSION`，拉取镜像，停止 Web / Worker，再按对应版本的 Compose 配置启动；本版本不需要数据库降级。完成升级后可恢复原有定时升级。
