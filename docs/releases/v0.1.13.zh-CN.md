# v0.1.13 部署与升级指南

本版本将 Responses 请求改为 `store: true`，并兼容服务商在开启存储时仍返回加密推理内容的情况。

## 功能变化

- Responses 请求允许服务商保存响应。`store` 控制响应存储，与自动提示词缓存的启用独立。
- 收到加密推理内容时优先原样回传，避免 SDK 因为同时存在条目 ID 而仅发送 `item_reference`。同一推理条目的多个流式摘要合并，保留完整摘要及加密状态。
- 没有加密内容但有响应条目 ID 时，通过 ID 引用存储的推理；没有可恢复状态的摘要不回传。文本、工具调用及工具结果继续保留。
- 多轮请求只追加新的历史，保持已有请求前缀和工具定义稳定。实际缓存命中由模型服务商决定。

## 验证

模拟网关已复现开启存储后加密内容被条目引用替代的问题，修复后通过真实 AI SDK 流式调用回归。测试覆盖默认与显式推理强度、带或不带加密内容、没有条目 ID、多个摘要片段、历史不可变性和连续三轮请求前缀稳定性。

262 项单元测试、类型检查、Lint 和格式检查通过，Web 与 Worker 生产构建均通过。

## 升级

从 v0.1.12 升级没有新增数据库迁移或必填环境变量，Web 与 Worker 使用同一版本。镜像支持 `linux/amd64`：

```text
ghcr.io/tairuiqu/oh-my-paper:v0.1.13
ghcr.io/tairuiqu/oh-my-paper-worker:v0.1.13
```

发布同时更新 `latest`。固定版本时将部署 `.env` 的 `APP_VERSION` 设为 `v0.1.13`，在部署目录执行：

```bash
docker compose -f compose.yaml -f compose.release.yaml pull migrate web worker
docker compose -f compose.yaml -f compose.release.yaml stop web worker
docker compose -f compose.yaml -f compose.release.yaml run --rm migrate
docker compose -f compose.yaml -f compose.release.yaml up -d --wait web worker proxy
docker compose -f compose.yaml -f compose.release.yaml ps -a
```

确认 Web、Worker 为 `healthy`，页面显示 `v0.1.13`。从更早版本升级需执行此前迁移，参见 [v0.1.12 升级指南](v0.1.12.zh-CN.md)和[通用部署手册](../deployment.zh-CN.md)。
