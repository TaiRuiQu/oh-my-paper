# v0.1.5 部署与升级指南

Worker 镜像改用独立运行目录：通过 esbuild 编译应用入口，使用文件追踪保留运行依赖，不再复制完整 `node_modules`、应用源码或 TypeScript 加载器。保留 Prisma 迁移命令、迁移引擎、健康检查、Sharp 原生组件和 Python 沙箱。Worker 构建不再依赖 Next.js 构建。快速批改的「标准答案（可选）」默认收起；展开即可上传，收起后摘要保留已选文件数量。

## 升级

本版本无新增数据库迁移或必填环境变量，Web 和 Worker 使用相同版本。已发布镜像支持 `linux/amd64`：

```text
ghcr.io/tairuiqu/oh-my-paper:v0.1.5
ghcr.io/tairuiqu/oh-my-paper-worker:v0.1.5
```

暂停原有定时升级后，在部署目录获取本版本并备份：

```bash
cd /opt/oh-my-paper
git fetch origin --tags
git checkout --detach v0.1.5
sudo bash scripts/backup.sh /var/backups/oh-my-paper
sudo install -m 600 .env /var/backups/oh-my-paper/pre-v0.1.5.env
```

保留数据库、存储目录及密钥，在 `.env` 中设置 `APP_VERSION=v0.1.5`。当前 shell 若设置了 `APP_VERSION`，先执行 `unset APP_VERSION`。更新 Compose 配置后执行：

```bash
docker compose -f compose.yaml -f compose.release.yaml pull migrate web worker
docker compose -f compose.yaml -f compose.release.yaml stop web worker
docker compose -f compose.yaml -f compose.release.yaml up -d db
docker compose -f compose.yaml -f compose.release.yaml run --rm migrate
docker compose -f compose.yaml -f compose.release.yaml up -d --wait web worker proxy
docker compose -f compose.yaml -f compose.release.yaml ps -a
docker compose -f compose.yaml -f compose.release.yaml logs --tail=100 migrate web worker
```

迁移成功后启动应用；Web 和 Worker 应显示 `healthy`。本版本的健康检查入口改为 `scripts/worker-health.mjs`，必须同步更新 `compose.yaml`，避免旧配置继续调用已移除的 `tsx` 和 `.ts` 入口。自定义启动命令应改为 `node --conditions=react-server worker/index.mjs --production`；迁移命令仍为 `node node_modules/prisma/build/index.js migrate deploy`。

首次部署及源码构建参见[通用部署手册](../deployment.zh-CN.md)。需要回滚至 v0.1.4 时，同步切换代码 tag 与 `.env` 的 `APP_VERSION`，拉取镜像，停止 Web / Worker，再按对应版本的 Compose 配置启动；本版本不需要数据库降级。完成升级后可恢复原有定时升级。

## 验证范围

执行格式检查、Lint、类型检查、单元测试和 Worker 产物构建。按本次要求不执行端到端测试；Docker 镜像构建由发布工作流完成。
