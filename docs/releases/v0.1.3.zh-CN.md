# v0.1.3 部署与升级指南

本版本新增试卷软删除、手动题目编辑，以及参照数学示例的横向四栏 PDF/Word 导出。发布镜像为：

```text
ghcr.io/tairuiqu/oh-my-paper:v0.1.3
ghcr.io/tairuiqu/oh-my-paper-worker:v0.1.3
```

镜像支持 `linux/amd64`。需要 Docker Compose v2.24 或更新版本；ARM 服务器使用下文的源码构建方式。完整环境配置见[通用部署手册](../deployment.zh-CN.md)。

## 从已有版本升级

以下命令在部署服务器的仓库目录执行，示例目录为 `/opt/oh-my-paper`。需要 Docker 操作权限。升级期间停止 Web 和 Worker，安排短暂维护窗口，避免旧 Worker 在迁移后继续使用旧代码。

1. 暂停自动升级（如果已启用定时器），记录原来的版本和镜像，然后获取版本源码。若部署目录有自行修改的文件，先保留修改，再切换 tag。

   ```bash
   cd /opt/oh-my-paper
   sudo systemctl stop oh-my-paper-update.timer
   git describe --tags --always
   docker compose -f compose.yaml -f compose.release.yaml images
   git fetch origin --tags
   git checkout --detach v0.1.3
   ```

   未使用 systemd 定时器时跳过 `systemctl`；使用 cron 自动升级时暂停对应条目。

2. 备份数据库、试卷文件和配置。备份脚本暂时停止写入服务，结束后自动重新启动它们。

   ```bash
   sudo bash scripts/backup.sh /var/backups/oh-my-paper
   sudo install -m 600 .env /var/backups/oh-my-paper/pre-v0.1.3.env
   ```

   记录脚本输出的备份目录。保留原来的 `BETTER_AUTH_SECRET` 和 `PROVIDER_KEY_ENCRYPTION_KEY`，升级时无需更换密钥。

3. 在 `.env` 中新增或更新这一行，将 Web、Worker 和迁移服务固定到同一版本：

   ```dotenv
   APP_VERSION=v0.1.3
   ```

   如果当前 shell 导出了其他 `APP_VERSION`，先执行 `unset APP_VERSION`，避免覆盖 `.env`。本版本没有新增必填环境变量。

4. 拉取镜像，停止旧代码，再明确执行迁移。迁移成功后启动新版本：

   ```bash
   docker compose -f compose.yaml -f compose.release.yaml pull migrate web worker
   docker compose -f compose.yaml -f compose.release.yaml stop web worker
   docker compose -f compose.yaml -f compose.release.yaml up -d db
   docker compose -f compose.yaml -f compose.release.yaml run --rm migrate
   docker compose -f compose.yaml -f compose.release.yaml up -d --wait web worker proxy
   ```

   `migrate` 返回 0 才继续最后一条命令。失败时保留日志并排查，不启动新版应用。此处不删除数据库卷，也不清理旧版镜像，以便回滚。

本版本新增迁移 `20261013020000_exam_edit_and_delete`，为 `exam_tasks` 添加 `deletedAt`，为 `exams` 添加 `revision`，为 `exam_agent_tasks` 添加 `examRevision`。已有试卷默认未删除，已有试卷及答案任务的版本为 0；迁移保留原来的题目、答案、批改记录和文件。

## 健康检查与功能验收

```bash
docker compose -f compose.yaml -f compose.release.yaml ps -a
docker compose -f compose.yaml -f compose.release.yaml logs --tail=100 migrate web worker
docker compose -f compose.yaml -f compose.release.yaml exec -T web node -e \
  'fetch("http://localhost:3000/api/health").then(async r=>{console.log(await r.text());process.exit(r.ok?0:1)}).catch(()=>process.exit(1))'
```

Web 和 Worker 应为 `healthy`，健康接口应返回 `{"status":"ok","database":"ready"}`。默认 Compose 没有将 Web 的 3000 端口映射到宿主机，因此使用上述容器内检查，或通过真实 HTTPS 域名访问 `/api/health`。

登录后用测试试卷完成以下验收：

- 打开详情页，点击「编辑试卷」，修改题干、小问或分值并保存；刷新后修改仍在，配图保留。
- 保存后为新版试题重新生成或上传标准答案。旧版答案不会自动用于新批改；历史批改结果仍可查看。运行答案或批改任务时，保存编辑会提示等待任务结束。
- 导出 PDF 和 Word，确认横向四栏、题号与正文同行、选项横排、公式和配图完整。Word 的文字与表格可编辑，公式为图片。
- 删除测试试卷，确认用户列表与批改试卷选择中不再出现；管理员在「试卷记录审查」中仍能打开试卷，并看到「用户已删除」。软删除保留文件，不会释放其存储空间。

镜像内已包含 Chromium、中文字体和导出依赖，无需服务器另行安装浏览器。Web 和 Worker 仍需共用 `storage/`、数据库、加密密钥与 `QUEUE_SCHEMA`。

## 首次部署

```bash
git clone --branch v0.1.3 --depth 1 https://github.com/TaiRuiQu/oh-my-paper.git /opt/oh-my-paper
cd /opt/oh-my-paper
cp .env.example .env
sudo install -d -o 1000 -g 1000 -m 0750 storage tmp
```

编辑 `.env`，将示例密码和密钥替换为真实配置，并加入 Compose 部署变量：

```dotenv
POSTGRES_USER=paper
POSTGRES_DB=oh_my_paper
POSTGRES_PASSWORD=<数据库密码>
DEPLOY_DATABASE_URL=postgresql://paper:<URL编码后的数据库密码>@db:5432/oh_my_paper
APP_DOMAIN=paper.example.com
BETTER_AUTH_URL=https://paper.example.com
BETTER_AUTH_SECRET=<至少32字符随机密钥>
PROVIDER_KEY_ENCRYPTION_KEY=<另一个至少32字符随机密钥>
APP_VERSION=v0.1.3
```

两个随机密钥分别使用 `openssl rand -base64 32` 生成。域名需要指向服务器，80/443 端口需要可达。私有 GHCR 镜像需先使用具有 `read:packages` 权限的凭据登录。

```bash
docker compose -f compose.yaml -f compose.release.yaml pull
docker compose -f compose.yaml -f compose.release.yaml up -d --wait
```

Compose 自动先完成迁移再启动应用。按上文检查健康状态，然后注册管理员账号：第一个注册账号自动成为管理员，应由部署者先完成注册。在 `/admin/ai` 配置支持图片的模型，并对普通用户开放所需模型。

## 源码部署

切换至 `v0.1.3`，配置与备份方式相同。只使用 `compose.yaml`，不加入镜像覆盖文件：

```bash
docker compose build web worker migrate
docker compose stop web worker
docker compose up -d db
docker compose run --rm migrate
docker compose up -d --wait web worker proxy
```

本机构建使用 Dockerfile 的 Web 和 Worker 目标。`APP_VERSION` 对源码构建不生效。

## 回滚与自动升级

需要回滚到 `v0.1.2` 时，将 `.env` 中的 `APP_VERSION` 改为 `v0.1.2`，再执行：

```bash
docker compose -f compose.yaml -f compose.release.yaml pull web worker
docker compose -f compose.yaml -f compose.release.yaml stop web worker
docker compose -f compose.yaml -f compose.release.yaml up -d --no-deps --wait web worker
```

本次迁移只增加字段，回滚代码时保留这些字段即可，不执行数据库降级。旧版不支持软删除和版本过滤，因此已删除的试卷会重新出现在旧版用户列表，编辑前的答案也可能重新参与旧版答案选择；如需恢复到升级前的完整业务状态，使用数据库和 `storage/` 的同一份升级前备份，并保留原加密密钥，参照 `scripts/restore.sh` 的使用说明操作。

固定 `APP_VERSION=v0.1.3` 时，重新启用定时器仍只跟踪该固定版本。希望继续自动跟随发布时，删除 `.env` 中的 `APP_VERSION`，再恢复定时器或 cron：

```bash
sudo systemctl start oh-my-paper-update.timer
```

后续 tag 发布会同时更新两个镜像的 `latest` 标签，`deploy/update.sh` 拉取后按 Compose 依赖运行迁移并更新服务。
