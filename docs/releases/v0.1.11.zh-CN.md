# v0.1.11 部署与升级指南

本版本修复 Responses 流式工具调用的缺字段兼容问题，并新增删除 AI 提供商功能。

## 功能变化

- 部分网关在 `response.output_item.added` 的 `function_call` 项中省略 `arguments`，会被 SDK 拒绝。现在仅为该起始事件补上空字符串，后续参数增量、完整参数和其他字段仍由 SDK 校验。兼容层逐事件处理 SSE，支持分片 UTF-8、CRLF、多行数据、心跳、连接错误和取消，不等待完整响应体。
- AI 设置中新增提供商删除入口，先显示影响说明，再确认删除。删除同时移除模型、关联的功能默认模型和用户选择；需重新配置相应功能。已有任务快照、答案和用量流水保留，运行中的任务使用原快照。删除接口只允许管理员同源请求。

## 验证

用户提供的原始缺字段事件已复现失败，修复后通过真实 SDK 回归。格式检查、Lint、类型检查、253 项单元测试和数据库集成测试通过；集成测试验证删除级联、默认模型清除，以及历史任务与用量记录保留。

浏览器验证覆盖桌面和手机布局、取消删除、确认删除、关联默认模型清除、其他提供商配置保留及刷新后的持久化。Web 与 Worker 生产构建均通过。

使用 `https://api.deepseek.com/responses` 和 `deepseek-flash` 完成真实后台答案任务端到端测试：两道计算题经过列题、批量读题、保存答案和最终提交共四轮调用，数据库任务为 `COMPLETED`，答案分别为 `56` 和 `x=4`，两题均保存评分标准。四轮 token 用量与 credit 结算均成功，测试折算消耗 `0.85466` credit。该数值为应用计价，不是提供商账单金额。测试采用隔离数据库 schema 和临时文件，凭据不写入仓库。

可复用实测脚本为 `scripts/test-live-answers.ts`。这是会消耗模型额度的手动测试；通过 `LIVE_AI_KEY_FILE` 或 `LIVE_AI_API_KEY` 提供凭据，可通过 `LIVE_AI_BASE_URL` 和 `LIVE_AI_MODEL` 设置接口与模型。成功报告保存在本地 `.local/live-answers-report.json`，结束后删除测试 schema 和临时任务文件。

## 升级

从 v0.1.10 升级没有新增数据库迁移和必填环境变量，Web 与 Worker 使用同一版本。镜像支持 `linux/amd64`：

```text
ghcr.io/tairuiqu/oh-my-paper:v0.1.11
ghcr.io/tairuiqu/oh-my-paper-worker:v0.1.11
```

发布同时更新 `latest`。固定版本时将部署 `.env` 的 `APP_VERSION` 设为 `v0.1.11`，在部署目录执行：

```bash
docker compose -f compose.yaml -f compose.release.yaml pull migrate web worker
docker compose -f compose.yaml -f compose.release.yaml stop web worker
docker compose -f compose.yaml -f compose.release.yaml run --rm migrate
docker compose -f compose.yaml -f compose.release.yaml up -d --wait web worker proxy
docker compose -f compose.yaml -f compose.release.yaml ps -a
```

确认 Web、Worker 为 `healthy`，页面显示 `v0.1.11`。此前因缺字段失败的答案任务可点击重试，保留已保存草稿。

从 v0.1.9 或更早版本升级还需同步仓库的 Compose 配置并执行布局等迁移，参见 [v0.1.10 升级指南](v0.1.10.zh-CN.md) 和[通用部署手册](../deployment.zh-CN.md)。
