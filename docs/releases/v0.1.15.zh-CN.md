# v0.1.15 部署与升级指南

本版本为 OpenAI Responses 接入添加稳定的会话和缓存标识，生成规则与 Codex 普通会话一致。

## 功能变化

- 新任务使用当前时间和随机数生成 UUIDv7，以同一个小写、带连字符的 UUID 原样设置 `session-id` 请求头和 `prompt_cache_key` 请求体字段。
- 试卷识别、答案生成与提取、学生批改、答题卡定位与评分均使用持久化任务 ID；同一任务的多轮调用、SDK 自动重试和失败后重试保持相同标识。
- 已有任务恢复时保留原 ID；独立创建模型实例时默认生成一次 UUIDv7。不同任务的标识相互独立。
- 缓存命中量继续使用提供商实际报告的 `cached_tokens`；添加标识不保证供应商缓存命中。

## 验证

276 项单元测试通过。真实 SDK 请求测试覆盖会话字段发送、多轮工具调用、HTTP 自动重试、模型重建后恢复任务及旧 UUID 的兼容性；数据库和答题卡集成测试验证新任务 UUIDv7 与失败恢复。类型检查、Lint、格式检查和 Web、Worker 生产构建通过，Worker 独立运行目录已验证包含 UUIDv7 依赖。

## 升级

从 v0.1.14 升级没有新增数据库迁移或必填环境变量。Web 和 Worker 使用同一版本，镜像支持 `linux/amd64`：

```text
ghcr.io/tairuiqu/oh-my-paper:v0.1.15
ghcr.io/tairuiqu/oh-my-paper-worker:v0.1.15
```

发布同时更新 `latest`。固定版本时将部署 `.env` 的 `APP_VERSION` 设为 `v0.1.15`，在部署目录执行：

```bash
docker compose -f compose.yaml -f compose.release.yaml pull migrate web worker
docker compose -f compose.yaml -f compose.release.yaml stop web worker
docker compose -f compose.yaml -f compose.release.yaml run --rm migrate
docker compose -f compose.yaml -f compose.release.yaml up -d --wait web worker proxy
docker compose -f compose.yaml -f compose.release.yaml ps -a
```

确认 Web、Worker 为 `healthy`，页面显示 `v0.1.15`。已有任务、试卷、答案和批改记录保留。从更早版本升级参见[通用部署手册](../deployment.zh-CN.md)。
