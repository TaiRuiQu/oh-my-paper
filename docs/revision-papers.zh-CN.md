# 错题复现与巩固卷

入口为「首页 → 错题复习组卷」。教师也可以从学生学情中的「错题复现」「生成巩固卷」进入；学生可以从「我的错题」进入。入口会保留已有的学生、教学安排、作业／考试范围和学生端学科筛选。

选择学生、学科和教学安排后，可以逐条选择错题。每次最多选择 500 条错题记录，一份题本只包含一个学科。

## 错题复现

将所选历史错题快照保存为独立题本，保留题干、配图、参考答案、解析、完整混合题小问及原题满分。来源题目、评分和题库均不被修改。相同来源 ID、版本和分值的重复题目合并；内容或分值不同的版本分别保留。

`POST /api/platform/revision-papers` 接收 `{studentId,name,subject,sources:[{assessmentId,itemId}]}`，返回 `{id,count}`。客户端只能提交来源标识，题目内容、权限和分值由服务器重新解析。

## AI 巩固卷

选择题数（1–20）、每题分值和已启用模型，创建 `CONSOLIDATE` 任务。输入为上述来源字段加 `{count,score}`，提交到现有 `/api/platform/ai` 队列。后台仍使用 `ToolLoopAgent` 自主检索、读取、查看图片、选择题目和完成任务，没有固定的模型调用顺序。

候选题须与来源错题同学科、同年级，且覆盖失分知识点；混合题仅以失分小问的知识点匹配。来源跨年级时，以首条所选错题的年级为准。教师使用自己的可访问题库，管理员使用全站题库；学生仅使用所选错题出题方的相关题库。排除已提交作答的题目及相同题干，包含尚未发布成绩的作答；这些内部排除信息不向学生返回。

题库不足时，在入队前明确提示可用题数，不调用模型。Agent 必须先读取错题和所选候选题，查看候选配图，再提交准确数量、无重复的真实题目及逐题选题理由。无法辨认的题目记录为跳过项；跳过后不足题数时可以正常结束，但不保存缩水卷。来源、选题理由和跳过项保存在任务结果中。

## 保存、导出与权限

两种卷均保存为创建者拥有的 `Paper(kind=HOMEWORK)`，直接使用现有 `items` JSON 快照，不增加数据库表或迁移。题本拥有独立题项 ID；跨账号的授权配图复制为创建者资产，事务失败时清理新文件。

题本预览位于 `/workspace/revision-papers/{id}`，提供参考答案、Word 导出及浏览器打印／保存 PDF。教师可以进入现有作业编辑器调整排版并按现有流程布置。学生可以查看、导出自己生成的题本；普通题库、题本编辑和教学写命令仍需要教师权限。

教师仅能使用当前教学权限覆盖的学生与学科；学生只能使用本人已发布成绩中的错题。AI 提交时持有教学写锁，重新验证任务归属、来源错题、候选题和学生作答，将新题本与任务完成状态一起提交。权限撤销、来源评分改变、候选题修改或新增作答使候选失效时，不保存过期结果。

## 验证

- `pnpm exec vitest run tests/revision-papers.test.ts`：来源校验、历史版本去重、混合题知识点和结果链接。
- `node --conditions=react-server --import tsx scripts/test-revision-papers.ts`：在隔离 PostgreSQL schema 验证原题与配图复制、学生隔离、候选过滤、精确题数、Word 导出、不可辨认题目及提交时变更／权限保护；测试结束清理数据库和图片文件。
- 浏览器验证教师和学生的生成入口、选题、保存预览、题库不足反馈，以及桌面和手机布局。回归测试不发起付费模型调用。
