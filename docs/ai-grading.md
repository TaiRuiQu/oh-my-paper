# AI 批改

识别结果页点击“核对作答并批改”。系统填入独立识别的学生作答、参考答案和评分标准；可修改作答、补充分值、选择需要批改的题目。作答留空明确按未作答处理，“作答无法辨认”保留待核对。识别标记为待核对的题目，可先对照原图确认内容；题干仍包含 `[unreadable]` 或必要材料/配图缺失时，服务保留不判分状态。

## 判分流程

有参考答案时，模型依据固定答案、满分和评分标准逐题判分。未提供参考答案时，先以干净题目及材料独立求解，再用独立请求核对参考答案，然后批改。两次求解请求不接收学生作答、教师批注或历史分数。缺失或污染的必要配图不会用于独立求解。AI 生成的答案和分数建议保留为待确认结果。

报告区分“计入总分”与“建议得分”。缺少分值、主观评分标准、无法辨认或出现矛盾时，需要人工核对。评分点得分不能超过该点满分，其满分和得分合计必须分别等于本题满分与模型给出的分数；判定与分数也须一致。不一致的数值保留待核对，不通过截断或强制归零来伪装为正常成绩。总分由程序以整数分币计算，并只累计已通过校验或已人工确认的题目。

“核对或调整分数”允许确认得分、满分与核对说明。修改保留原模型建议、评分点及人工记录，并由服务重新汇总。后台数据库行锁避免并发核对互相覆盖。模型失败与未作答分别处理，失败题不自动记零分。Markdown 和 JSON 报告可下载。

## 模型、提示词和缓存

管理员可分别指定识别和批改模型；未单独指定批改模型时，使用当前识别模型。任务保留提交时的模型配置、加密密钥、题目和作答快照，重新识别不会修改历史批改报告。

五套提供商预设分别用于识别和批改。批改固定前缀包含角色、证据边界、评分原则、序列化规则和格式示例；阶段规则在后，当前题目、材料、固定答案和作答放在 user 消息中。相同评分 schema 在每题复用，前缀不插入任务 ID、题号或日期。Anthropic 在固定前缀处设置缓存断点；其他协议使用服务商的缓存机制。报告记录 API 返回的输入、输出、缓存读取/写入 token 数及调用数，缓存命中不能保证。

官方提示词与缓存依据见 [AI 提供商和提示词指南](ai-providers-and-prompts.md)。这些是应用编写的预设，不是提供商认证的判分规则。

## 后台与范围

每次最多 100 道题、每用户最多 3 个同时批改任务，同一试卷同时只有一个批改任务。每批默认最多 300 次模型调用，超过后保留未完成题目；批改运行最多 2 小时。JSON 修复也占用调用预算，修复失败仍记录已返回的用量；有明确预算时关闭 SDK 内部网络重试，避免额外请求绕过预算。写任务与入队共用数据库事务。逐题保存检查点；Worker 中断重试时复用已完成题目，不重复生成已保存评分。队列心跳发现进程退出，数据库状态与队列终态同步。全部报告、人工修改和下载检查试卷归属。

当前入口针对用户自己的已识别试卷。独立答案文件、多人班级批次、制度化成绩发布和错题档案需要后续业务对象。现有字段允许补充参考答案、主观题标准和人工分数，不把 AI 建议作为未经复核的正式成绩。

## 验证

```bash
pnpm db:generate
pnpm db:deploy
pnpm dev:all
pnpm test
# 两条真实 DeepSeek 流程的集成测试；使用 .env 的密钥并产生 API 费用
pnpm test:exam-web --live --keep
pnpm test:grading-web --keep
# 浏览器验证完成后清理临时账号、模型和报告，恢复原模型选择
pnpm test:grading-web --cleanup
pnpm test:exam-web --cleanup
```

自动测试覆盖评分点校验、部分分、缺失资料、未作答/无法辨认分离、单题失败、人工确认、题号重置和断点恢复。真实集成测试使用清楚标记的合成两题数学试卷（错误计算答案与正确选择答案），验证带参考答案的 5/10 分和无参考答案的待确认流程。这不等于真实学科试卷的判分准确率基准。
